# Vehicle Dynamics - Straight Motion Error 해결 방법론

## 1. 목표

현재 직진 주행은 주로 다음과 같은 단순 모델에 의존하고 있다.

```text
주행 명령 시간
    ↓
예상 이동거리
```

예를 들어 다음과 같은 형태이다.

```text
1초 전진 ≈ 0.284 m
```

하지만 실제 지게차는 다음 이유로 인해 동일한 명령에서도 최종 이동거리가 매번 조금씩 달라질 수 있다.

- 출발 명령 이후 실제 움직임이 시작되기까지의 지연
- 주행 중 속도의 미세한 변화
- 정지 명령 이후 실제 감속 시작까지의 지연
- 정지 과정에서 발생하는 관성 이동
- 바닥 마찰, 하중, 배터리 상태 등 차량 동역학의 변화

따라서 직진 제어의 목표는 단순히

```text
"몇 초 움직일 것인가?"
```

를 계산하는 것이 아니라,

> **현재 상태에서 지금 정지 명령을 내리면 최종적으로 어디에 멈출지를 예측하는 것**

으로 변경하는 것이 좋다.

---

# 2. 현재 문제

## 2.1 명령 시간과 실제 주행 시간의 불일치

예를 들어 코드가 다음과 같다고 하자.

```python
move_forward()
time.sleep(2.0)
stop()
```

컴퓨터는 다음과 같이 해석한다.

```text
0.0 s : Forward 명령
2.0 s : Stop 명령
→ 2초 주행
```

하지만 실제 차량은 다음과 같이 움직일 수 있다.

```text
0.0 s : Forward 명령 전송
0.3 s : 실제 움직임 시작
2.0 s : Stop 명령 전송
2.2 s : 실제 감속 시작
2.5 s : 완전 정지
```

즉 `sleep(2.0)`은 실제 차량이 정확히 2초 동안 움직였다는 뜻이 아니다.

---

## 2.2 정지 관성

Stop 명령을 보내더라도 차량은 즉시 멈추지 않는다.

예:

```text
Stop 명령 시점
남은 거리 = 0.20 m

완전 정지 후
남은 거리 = 0.14 m
```

따라서 stop 이후 추가 이동거리는

\[
0.20 - 0.14 = 0.06m
\]

즉 6 cm이다.

이 추가 이동거리가 최종 docking 오차에 직접 영향을 준다.

---

## 2.3 동일 조건에서도 매번 결과가 달라짐

같은 차량, 같은 명령 시간, 비슷한 조건에서도 실제 이동량은 매번 조금씩 달라질 수 있다.

예:

```text
2.0초 Forward 명령

Trial 1 → 0.551 m
Trial 2 → 0.542 m
Trial 3 → 0.559 m
Trial 4 → 0.548 m
```

따라서 하나의 고정식으로 모든 상황을 완벽하게 설명하기 어렵다.

# 3. 핵심 방향

기존 구조:

```text
목표 거리
   ↓
고정식으로 주행 시간 계산
   ↓
Forward
   ↓
Stop
```

개선 구조:

```text
현재 위치
+
현재 속도
+
최근 가속도
+
차량의 정지 특성
    ↓
예상 정지거리 계산
    ↓
목표 지점과 비교
    ↓
적절한 시점에 Stop
```

즉 핵심은 다음 질문에 답하는 것이다.

> **지금 Stop을 보내면 차량이 앞으로 얼마나 더 이동할 것인가?**

# 4. 명령 지연시간 처리

명령 지연시간은 다음과 같이 여러 부분으로 나눌 수 있다.

## 4.1 출발 지연

Forward 명령을 보낸 시점부터 실제 차량이 움직이기 시작하기까지의 시간.

\[
t_{start\_delay}
\]

---

## 4.2 정지 반응 지연

Stop 명령을 보낸 시점부터 실제 감속이 시작되기까지의 시간.

\[
t_{stop\_delay}
\]

---

## 4.3 감속 및 관성 구간

감속이 시작된 이후 속도가 0이 될 때까지의 구간.

---

## 중요한 점

개발 초기에는 이 세 가지를 반드시 완벽하게 분리할 필요는 없다.

실제 목적은 지연시간 자체를 정확하게 아는 것이 아니라,

```text
Forward 명령
→ 실제 이동거리

Stop 명령
→ 최종 정지 위치
```

를 예측하는 것이다.

따라서 먼저 다음 관계를 직접 측정하는 것이 실용적이다.

\[
command\ duration
\rightarrow
actual\ displacement
\]

그리고

\[
stop\ command
\rightarrow
additional\ displacement
\]

---

# 5. 직진 사전 실험

## 5.1 Command Duration 실험

다양한 주행 시간을 반복 실행한다.

예:

```text
1.0 s
1.5 s
2.0 s
2.5 s
3.0 s
```

각 trial에서 다음을 기록한다.

```text
명령 전 forward
Forward command timestamp
Stop command timestamp
완전 정지 후 forward
실제 이동거리
```

예:

| Command Time | Actual Distance |
|---:|---:|
| 1.0 s | 0.21 m |
| 1.5 s | 0.36 m |
| 2.0 s | 0.55 m |
| 2.5 s | 0.70 m |

이 데이터를 통해 단순한 고정식보다 실제 차량에 맞는 주행 모델을 만들 수 있다.

---

# 6. Stop Distance 실험

정지 관성을 따로 측정한다.

각 trial에서 다음을 기록한다.

```text
Stop command 시점의 forward
Stop command 시점의 velocity
완전 정지 후 forward
```

추가 이동거리:

\[
d_{stop}
=
forward_{stop\ command}
-
forward_{final}
\]

예:

| Stop 시 속도 | Stop 후 추가 이동거리 |
|---:|---:|
| 0.05 m/s | 0.012 m |
| 0.10 m/s | 0.028 m |
| 0.15 m/s | 0.050 m |
| 0.20 m/s | 0.076 m |

이를 통해

\[
d_{stop} = f(v)
\]

형태의 정지거리 모델을 만들 수 있다.

초기에는 다음과 같은 단순 모델로 충분하다.

- Linear regression
- Polynomial regression
- Piecewise regression

처음부터 NN을 사용할 필요는 없다.

---

# 7. 가속도 활용

직진 제어에서 IMU의 선형 가속도는 매우 유용한 보조 정보가 될 수 있다.

단, IMU 가속도를 두 번 적분하여 위치를 직접 계산하는 방식은 권장하지 않는다.

```text
가속도
→ 적분
속도
→ 적분
위치
```

이 방식은 작은 IMU bias가 누적되면서 위치 오차가 빠르게 커질 수 있기 때문이다.

따라서 IMU 가속도는 다음 목적으로 사용하는 것이 좋다.

---

## 7.1 실제 출발 시점 감지

Forward 명령 timestamp와 IMU 가속도 변화를 비교한다.

예:

```text
10.000 s : Forward command
10.180 s : IMU acceleration 변화 시작
```

그러면 약 0.18초 후 실제 차량이 반응했다고 볼 수 있다.

이를 통해 출발 지연을 추정할 수 있다.

---

## 7.2 실제 감속 시작 시점 감지

Stop 명령 이후 음의 가속도 또는 감속 패턴이 나타나는 시점을 찾는다.

예:

```text
12.000 s : Stop command
12.140 s : 감속 시작
```

그러면 약 0.14초 정도의 반응 지연이 존재한다고 볼 수 있다.

---

## 7.3 정지 상태 판별

IMU 가속도와 AprilTag 기반 속도를 함께 사용하여 차량이 실제로 완전히 멈췄는지 판단할 수 있다.

예:

```text
AprilTag velocity ≈ 0
+
IMU acceleration 안정
+
일정 시간 position 변화 거의 없음
        ↓
Vehicle stopped
```

이렇게 하면 단순히 stop 명령을 보냈다는 이유로 차량이 이미 정지했다고 가정하지 않아도 된다.

---

## 7.4 정지거리 예측 보조

현재 속도만 보는 것보다 최근 감속도까지 보면 정지거리 예측을 개선할 수 있다.

예:

```text
현재 속도 = 0.20 m/s

Trial A:
감속 강함
→ 짧은 거리에서 정지

Trial B:
감속 약함
→ 더 긴 거리 이동 후 정지
```

따라서 향후에는 다음과 같은 모델을 고려할 수 있다.

\[
d_{stop} = f(v, a)
\]

여기서

- \(v\): 현재 속도
- \(a\): 현재 또는 최근 감속도

이다.

초기에는 우선 \(d_{stop}=f(v)\)로 시작하고, 속도만으로 설명되지 않는 오차가 크면 \(a\)를 추가하는 것이 좋다.

# 8. AprilTag와 IMU의 역할 분리

각 센서의 역할은 명확하게 나누는 것이 좋다.

## AprilTag

주요 역할:

```text
현재 위치
현재 forward
현재 lateral
현재 heading
```

즉,

> "지게차가 지금 어디에 있는가?"

를 담당한다.

---

## IMU Linear Acceleration

주요 역할:

```text
실제 출발 감지
실제 감속 시작 감지
정지 상태 확인
차량 반응 변화 확인
```

즉,

> "지게차의 움직임이 지금 어떻게 변하고 있는가?"

를 담당한다.

---

## IMU Gyro

회전에서는 다음을 담당한다.

```text
현재 yaw rate
회전 시작 여부
회전 감속 여부
각가속도 계산
```

이 부분은 회전 문제 해결에서 별도로 활용한다.

# 9. Perception과 연계

1번 Perception 단계에서 실시간으로 다음 값을 얻는다고 가정한다.

```text
estimated_forward
estimated_velocity
```

이 값이 2번 Vehicle Dynamics 제어의 핵심 입력이 된다.

예:

```text
현재 남은 거리 = 0.18 m
현재 속도 = 0.15 m/s
예상 정지거리 = 0.16 m
```

그러면 controller는

```text
현재 시점에서 Stop을 보내는 것이 적절함
```

이라고 판단할 수 있다.

따라서 1번과 2번은 독립된 문제가 아니라 다음과 같이 연결된다.

```text
Perception
   ↓
현재 위치 + 현재 속도
   ↓
Vehicle Dynamics Model
   ↓
예상 정지거리
   ↓
Controller
```


\[

\]

이면 Stop을 수행한다.

# 11. 저속 Final Approach

최종 docking 정확도를 높이기 위해 마지막 구간에서는 속도를 낮추는 것이 중요하다.

속도가 낮아지면 다음 항목이 모두 줄어든다.

- 정지 관성
- 지연시간 동안 추가 이동거리
- 매 trial마다 발생하는 정지 위치 분산
- detection 지연으로 인한 위치 오차

따라서 최종 접근을 다음과 같이 분리할 수 있다.

```text
Far Area
→ 일반 속도

Near Area
→ 감속

Final Area
→ 매우 낮은 속도
→ 실시간 정지 판단
```

# 핵심 결론

직진 문제는 단순히

```text
1초 = 0.284 m
```

와 같은 고정식을 더 정밀하게 만드는 것만으로 해결하기 어렵다.

핵심은 다음 세 가지이다.

1. **명령 시간과 실제 이동 결과를 분리해서 측정한다.**
2. **현재 속도를 이용해 Stop 이후 추가 이동거리를 예측한다.**
3. **IMU 가속도를 출발/감속/정지 판단과 정지거리 예측의 보조 정보로 사용한다.**

궁극적으로 제어 기준을

```text
"몇 초 움직일 것인가?"
```

에서

```text
"지금 Stop하면 어디에 멈출 것인가?"
```

로 변경하는 것이 목표이다.
