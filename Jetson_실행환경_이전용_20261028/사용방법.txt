젯슨 실행 환경 실행용 복사 — 2026-10-28

포함: 바탕화면 실행기 3종, 실행에 쓰이는 프로그램 코드·모델·현재 보정 설정, .venv-jetson 및 PyTorch 등 Python 의존성, 실행 시 확인한 시스템 Python/OpenCV 의존성, OpenCV/CAN 네이티브 라이브러리, RealSense/Kvaser 규칙과 Kvaser 커널 모듈. 영상·로그·과거 백업·벤치마크·개발 테스트·컴파일 캐시·중복 설치용 wheel/드라이버 소스는 제외했습니다. Python 패키지 내부 구성은 실행 호환성을 위해 보존하되 test/tests 및 바이트코드 캐시를 제외했습니다. 앱/모델은 수정하지 않았습니다.

사용 대상: 원본과 같은 ARM64 Jetson Orin 계열, Ubuntu 22.04, L4T R36.4.7, 커널 5.15.148-tegra, Python 3.10, CUDA 12.6/cuDNN 9.3 환경. 구형 Jetson Nano(JetPack 4)·다른 JetPack·다른 커널에서의 그대로 실행은 보장하지 않습니다. CUDA/NVIDIA 드라이버·OS 자체는 ZIP에 복제하지 않았습니다. SOURCE_SYSTEM.json 및 INSTALLED_APT.tsv에 원본 버전이 있습니다.

새 젯슨에서:
1. ZIP을 일반 사용자 권한으로 홈 폴더의 최종 위치(예: Downloads)에 압축 해제합니다. 파일/폴더는 복원 뒤 이동하지 마세요. USB에서 먼저 젯슨 내부 디스크로 복사하세요.
2. 압축 해제한 Jetson_실행환경_이전용_20261028 폴더의 터미널에서:
   bash RESTORE.sh --system
   sudo 비밀번호는 해당 새 젯슨 터미널에서 직접 입력합니다.
   모든 원본 파일의 SHA-256을 확인하고, 누락된 apt 의존성 설치 및 장치 규칙/모듈 등록, 현재 계정의 바탕화면 실행기 생성까지 수행합니다. apt 패키지가 누락되었다면 인터넷 연결이 필요합니다. 동일 환경에서 필요한 패키지가 모두 있으면 별도 다운로드 없이 복원합니다.
3. 로그아웃 후 다시 로그인하여 장치 권한 그룹을 적용합니다.
4. 해당 폴더에서 bash VERIFY_RUNTIME.sh 로 장치 없이 import/GPU 연산을 점검합니다.
5. 카메라·Kvaser를 연결하고, 바탕화면 '카메라·CAN 연결 확인' 후 기존 '차량제어 실행 (FSM v4)'을 사용합니다. RUN 입력과 모델 선택 방식은 원본 그대로입니다. 각 시연 후 종료 버튼을 누르고 창을 완전히 닫은 뒤 새로 실행합니다.
   바탕화면 실행기가 비활성화돼 있으면 우클릭→실행 허용을 선택합니다.

검증만: bash RESTORE.sh --verify-only (파일/시스템 수정 없이 플랫폼/파일 해시 확인)
이미 장치 규칙·커널 드라이버가 준비된 경우: bash RESTORE.sh (관리자 작업 없이 실행기/경로만 등록)
설치 실패시 오류를 해결한 뒤 다시 실행할 수 있습니다. 기존 바탕화면 실행기가 다르면 덮어쓰지 않습니다. 기존 파일을 이름 변경한 뒤 실행하세요.

경로가 달라도 앱 원본 대신 별도 실행 래퍼와 환경변수로 원본 Python 의존성을 연결합니다. ZIP은 Unix 권한과 심볼릭 링크를 보존하며 RESTORE.sh가 추출 도구의 링크/권한 손실을 복구합니다.
USB 자동실행의 물리 포트, Wi-Fi 비밀번호, Tailscale/SSH 키·등록정보, RustDesk 인증정보는 새 장치에 복제하지 않습니다. 이번 요청의 바탕화면 실행에는 USB 자동실행 등록이 필요하지 않습니다.

실제 다른 젯슨에서의 장치 연결/주행은 아직 검증하지 않았습니다. 포크·차량별 기하/카메라 위치·Kvaser/CAN 장치 차이가 있으면 현장 설정 점검이 필요합니다. 제공 복원/검증 도구는 차량 프로그램을 자동 시작하지 않습니다.
