### 쟁점 1: Timestamp 체계
- 판정: 부분동의 (단일 시계·t_capture=global_time·queue=1·6시각·TXACK 기록은 동의. 통과 기준과 폴백은 반박)
- 반박 근거: ① **상호상관 판정이 뒤집혔다.** ψ_cam 을 *t_capture* 축에, ψ_gyro 를 자이로 시각 축에 놓았을 때 두 스탬프가 모두 진짜 사건시각이면 최대 상관 지연 ε ≈ 0(±노출/2+롤링셔터 행, 10~15 ms) 이어야 한다. 80~110 ms 가 나오는 경우가 바로 "카메라 스탬프 = 도착시각" 이다. 제안대로 "80~110 통과·≈0 버그" 로 박으면 **옳게 찍힌 시스템이 게이트에서 떨어지고 도착시각을 쓰는 시스템이 통과**한다 → critic §7·FM5 가 "검증됨" 딱지를 달고 살아남는다. 파이프라인 지연 L = t_arrival − t_capture(기대 66~150 ms) 와 정합 잔차 ε 는 별개 양인데 한 숫자로 뭉쳤다. ② 폴백 `time_of_arrival − 66 ms`: B27 의 66 ms 는 realsense-ros 파이프라인 값이고 우리는 1080p YUYV→BGR+파이썬(`image.py:423-449`) — 다른 경로에 상수 지연을 박는 것은 §7 이 금지한 바로 그 가정이며 상수 최소화 원칙(실시간 도출 가능한 양) 위반. ③ 자이로: `imu_yaw.py:153` 은 `m.get_timestamp()`(장치 시각), `:166` `monotonic` 은 alive 전용 → 모션 모듈이 global_time 이 아니면 컬러와 **다른 시계**여서 상호상관 자체가 무의미(proposer 도 리스크로 적었으나 대응이 "세션마다 실측" 뿐). ④ `movement_tx_loop` 는 같은 payload 를 10 ms 마다 재송신(`control_forklift_v2.py:50,413-428`) → t_cmd_tx 는 "**payload 가 바뀐 첫 프레임**" 으로 정의하지 않으면 매 10 ms 가 명령 시각이 된다.
- 대안: 시각 지표 2개로 분리 — L = t_arrival − t_capture(히스토그램) 와 ε = argmax xcorr(ψ_cam(t_capture), ψ_gyro). **통과 = L∈[50,150] ms ∧ |ε| < 15 ms.** ε 는 버리지 않고 세션 상수(노출 중심·readout 오프셋 합)로 KF 에 적용 → `T_READOUT_MS` 불필요. global_time 두 스트림 assert 실패 시 폴백 없이 **출발 거부(dry-run 만)**. t_cmd_tx = 변경 payload 첫 `ch.write()` 반환 직후 `time.time()`(광운대 `_write` 훅 이식) 을 런타임 1차로, TXACK 은 precheck 에서 (t_txack − t_write) 분포를 한 번 재어 p99 < 20 ms 면 FM8 감지·교차검증 전용. 상수: 새 config 0 / 실시간 도출 2(ε, L 통계) / 코드 내부 STALE.
- 대안 근거: Lee & Johnson 2020(B26)·PX4 EKF2(C3) 모두 지연을 *측정*해 되감을 뿐 상수 폴백을 두지 않음; Larsen 1998 외삽도 τ 를 입력으로 받는다. ε 실측이 곧 §7 "타임스탬프가 진짜 캡처 시각인지 확인" 의 유일한 직접 증거. `ch.write()` 는 드라이버 큐 진입 시각이라 버스 송신과 500 kbps 에서 ≲수 ms 차 — 우리가 재는 물리(τ_d 0.5 s, σ_τ 50~100 ms, 자이로 5 ms)보다 한 자리 작다.
- 실차 검증법: 정지 60 s + 8°/s 회전 ×3 에서 L·ε 산출 → 검출 스레드에 **300 ms 인위 sleep 주입** 후 재실행: L 이 +300 ms 이동하고 ε 이 그대로면 스탬프가 캡처 기준(통과), ε 도 +300 이면 도착시각(실패). 뒤집힌 판정이면 이 실험이 정반대 결론을 낸다.

### 쟁점 2: Perception 오차와 Dynamics 오차 분리
- 판정: 부분동의 (캘리브 사슬·게이트 미통과 시 dynamics 셀 거부·해시 최소화는 동의. 회귀 검정과 ①−② 분류는 반박)
- 반박 근거: ① "① 잔차를 (t_arrival − t_capture) 에 회귀" — queue=1 이면 L 의 세션 내 산포는 10~20 ms → 회귀변수 분산이 거의 0, 효과 크기 v·σ_L ≈ 3~6 mm < σ_e 2 cm → 기울기 b 는 **식별 불가**(약한 도구변수). 수동 회귀는 CI 가 넓어 항상 "≈0" 으로 통과 = 거짓 안심. 300 ms 주입은 옳지만 그건 설계실험이지 회귀가 아니다. ② 방법 ② 는 t_resp(가속도 전이) 와 t_stop,IMU 를 요구하는데 plan 2-3 이 "검출률 미확인" 으로 둔 양 — 검출된 정지만 ②가 있으면 ①−② 비교가 "깨끗한 정지" 로 편향(선택 편향). 게다가 ②도 v̂(카메라 KF) 를 쓰므로 ①과 독립이 아니다 → 차이 > 2 cm 를 "이동 중 perception 바이어스" 로 분류하는 것은 램프 형태 오차·t_stop 오검출과 구별 불가(제안의 리스크 항이 인정). ③ 사슬 순서 timing → perception → dynamics 가 **쟁점 7 의 Day 0 정적 격자(timing_calib 이전)** 와 모순 — 정적 b·θ_min·σ_c·SPRT 는 타이밍과 무관하고, A·s·δ·ε 같은 이동 종속 항목만 timing 이 선행한다. ④ plan 2-1 의 D_obs = KF x̂(t_cmd) − 정지 중앙값은 KF 지연(Q)을 그대로 흡수하는데(plan 2-6 해시 규칙의 이유) L 회귀는 KF 지연을 볼 수 없다.
- 대안: (a) `perception_calib.json` 을 **static 절(무의존)** 과 **dynamic 절(timing 해시 종속)** 로 나눠 사슬을 timing → {perception.dynamic, dynamics} 로 고친다. (b) 스탬프 무결성은 쟁점 1 의 L 주입 {0,150,300} ms × 67 정지 n≥5 씩 **설계실험** 하나로 끝낸다(|b| < 0.1·v). (c) ②·분류 삭제. 대신 매 정지에 D_obs 를 두 갈래 — KF x̂(t_cmd) 기준 / **t_cmd 에 가장 가까운 원시 프레임 pose 기준(KF 없음)** — 로 계산해 차이를 *진단 로그*로만 남긴다: 이 차이가 곧 KF 지연이며 새 추론이 없다. 상수: 새 config 0 / 실시간 도출 1(KF-원시 차) / 캘리브 파일 신설 1(timing).

### 쟁점 3: 99% 성공 정의 — tolerance 확정과 KPI
- 판정: 부분동의 (도면 기하에서 tolerance 도출·(n, 실패, 95% 하한) 보고·k-factor 조건부·외부 진값·STABLE_* 삭제는 전부 동의. 결합영역의 형태와 격자 구성은 반박)
- 반박 근거: ① `|e_l| + D·tan|e_h| ≤ c` 는 **다이아몬드**인데 물리는 **평행사변형**이다: 포크가 heading e_h 로 D 만큼 밀려 들어갈 때 구속은 "끝단이 안에 있고(|e_l,tip| ≤ c) 입구 통과점도 안에 있다(|e_l,tip − D·tan e_h| ≤ c)" 두 개. (e_l, D·tan e_h) 공간에서 다이아몬드 넓이 2c² vs 평행사변형 4c² → **가장자리에서 최대 2배 과보수**, e_l = +c 일 때 진짜 허용 e_h 는 [0, atan(2c/D)] = [0, 3.4°](D=1) 인데 다이아몬드는 0° 만 허용. plan 3-0 이 "T 회전 양자화가 30 mm 예산을 거의 소진" 이라 결론한 상황에서 T_h 를 인위로 절반으로 깎으면 "99% 불가" 판정이 기하 정의 탓으로 과장된다. ② 시작 격자 d{6,8}×ℓ{0,±1,±2}×ψ 30 셀 중 **d=6·ℓ=±2 의 6 셀은 plan 3-4 포락선 밖**(2/(6−3.5)=0.8 > tan 31°=0.60) → dog-leg 경로를 시험하는 셀이 명목 KPI 에 섞인다; n=20 으로 30 셀 균등 추출도 불가. ③ "성공 = 결합영역 ∧ abort 없음" 은 헤드라인으로 옳지만 안전상 핵심 KPI 는 **false-DONE**(DONE 선언 ∧ 영역 밖) — abort(안전 실패)와 분리해 1차 KPI 로 올려야 한다(현재 목록엔 abort 율·DONE-unverified 만).
- 대안: 성공 판정은 x_ref = 포크 끝에서 **평행사변형** `max(|e_l|, |e_l − D·tan e_h|) ≤ c`, 여유 m = c − max(…) 를 trial 당 스칼라 KPI 로 보고(분위수가 곧 성공 확률; T_h 라는 별도 축·상수 불필요 → `HEAD_TOL_DEG` 삭제 가능). 정규화 다이아몬드는 controller 비용(critic §17) 전용으로만. 격자는 포락선 안(d 8 m 전체, d 6 m 은 ℓ≤1) 명목 셀과 포락선 밖 dog-leg 셀을 **분리 보고**. 1차 KPI = false-DONE 수(n=20 에서 0 필수), 2차 = m 분위수·abort 율(Tier·원인)·프리미티브 수·VERIFY 후 반전. 상수: 새 config 2(`FWD_TOL_M`, `INSERT_DEPTH_M`) + 포켓 c 는 `W_POCKET_M·W_FORK_M` 물리 2개(제안과 동일), 삭제 목록 그대로 + `HEAD_TOL_DEG`.
- 대안 근거: Walter 2010 의 "10~14 cm 삽입 성공" 은 허용영역이 포켓 기하·강성 종속임을 보이고, 다이아몬드는 그 기하의 절반만 인정한다. Köhne(≤20 mm/≤2.9°)·Kita(≤50 mm/≤3°) 의 "쌍 제시" 는 상자 보고 관행일 뿐 결합 형태의 근거가 아니다. critic §23 은 분위수·abort·correction 수를 요구하며 "false DONE" 은 그중 유일한 *안전* 지표.
- 실차 검증법: 명목 셀 n=20 최종 정지 외부 줄자(포크 끝 lateral·heading 각각) → (e_l, D·tan e_h) 산점도에 평행사변형과 다이아몬드를 겹쳐 그림. 두 영역 판정이 갈리는 trial 수가 곧 과보수 비용; false-DONE = 0 확인.

### 쟁점 4: Failure mode 7종(+FM8·FM9)
- 판정: 부분동의 (FM 코드·감지 신호·대응·고장주입 1:1, FM8·FM9 추가, 9/7 재분류 가설은 동의. FM8 대응 범위·FM1 신호·FM3 시험 해석·FM7 정의는 반박)
- 반박 근거: ① **FM8 이 실제 9/7 사건 클래스를 덮지 못한다.** "TX 전용 스레드 + 송신 데드맨" 은 *루프 지연*(GC·검출 스파이크)엔 듣지만, 9/7 꼬리는 plan 2-2 가 "VM **호스트** 사건" 으로 결론한 것 — 호스트가 얼면 같은 프로세스의 TX 스레드도 얼어 stop 프레임이 나가지 않는다. 그때 유일한 방어는 차량 워치독(FM9)인데 plan 3-7 이 "Curtis PDO Timeout 0 = 마지막 명령 유지" 가능성을 적었다 → 67 전진 중 호스트 정지 = 사람 제동까지 폭주. 제안 문면은 FM8 이 처리된 것처럼 읽힌다. ② FM1 감지 3종(pitch-cue SPRT·Δψ_cam−Δψ_IMU·innovation 부호)은 전부 **heading 신호**라 heading_valid=False 인 정면 원뿔·소형 태그 구간엔 없다 — 거기가 flip 이 사는 곳(Springer & Kyas 거리 증가). ③ FM3 시험 "181437 재생 반전 0" 은 기록된 상태에서 *결정만* 재생하는 개루프 — 새 명령에 대한 차량 반응은 로그에 없으므로 폐루프 ping-pong 부재의 증거가 아니다(그 역할은 쟁점 6 시뮬). ④ FM7: plan 3-6 이 구역을 거리 아닌 σ_F·σ_lat 로 정의했으니 chattering 은 이제 **σ 축**에서 생긴다(앵커 나이로 σ_F 가 T_l/2 를 되넘음) — 제안의 hysteresis 는 거리 성분(D̂+2σ_x)만 다룬다.
- 대안: FM8 을 두 층으로 갈라 적는다 — FM8a 루프 지연(데드맨 stop, 시험 = 검출 스레드 300 ms sleep) / **FM8b 호스트 정지(소프트웨어 대응 없음; 대응 = 차량 워치독 확인(plan 2-7(1)) 또는 "유지" 판정 시 사람 제동 + Jetson 베어메탈 호스트 규정, plan 에 '미완화 리스크' 로 명기)**. FM1 에 4번째 신호 추가: 직진 다리 ≥1 m 후 `sign(Δβ_px,obs) == sign(Δβ_pred(ψ̂))` 불일치 → AMBIGUOUS(자이로·PnP 무관, 정면에서도 산다). FM3 시험은 "결정 재생 반전 0" 으로 명명하고 폐루프 검증은 쟁점 6 으로 위임. FM6 감지의 dσ/dt 는 σ̂ 아닌 **σ_eff=max(cσ̂, σ_floor)** 로 — floor 지배면 즉시 Tier 1 이 맞다(FM2 와 결합 방지).
- 대안 근거: plan 2-2 (호스트 사건 분리)·3-7(ABORT = stop+heartbeat 지속, 워치독 미확인). Liu 2021(B8): 이동 중 재투영은 틀린 해를 고르므로 *예측 대비 기하 일관성* 이 해 선택 근거 — β 부호 검사가 그 최소형. critic §20 hysteresis 의 목적은 모드 안정성이며 단조 전이는 그 극한형(Nav2 docking 도 staging→dock 단방향, A12).
- 실차 검증법: 97 크립 중 **`kill -STOP` 2 s(프로세스 전체 동결, 사람 제동 위치)** — 데드맨 스레드까지 얼리는 유일한 FM8b 주입. 차량이 정지하면 워치독 존재·T_wd 실측, 계속 가면 "유지" 확정 → FM8b 미완화 명기. 별도로 검출 스레드 300 ms sleep(FM8a) 에서 stop 프레임 연속 확인.
