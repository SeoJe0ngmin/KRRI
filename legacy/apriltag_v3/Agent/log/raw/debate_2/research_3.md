- 근거 요약: (1) 표준형은 한결같이 "창 통계(분산·에너지·차분 EMA) < γ ∧ 지속(또는 EMA) + 히스테리시스(진입 0.7×/즉시 탈락)" 이고, γ·창은 도메인마다 18 ms~3 s 로 흩어지며 리뷰(3-2)도 "속도 의존·미해결" → **k·N·0.3 s 는 정지/크립 두 분포 실측 후 확정**이 문헌 입장. 문턱 도출 절차는 ArduPilot 식 "정지 로그 최대값 × 여유(SF)" 로 실시간화 가능(새 상수 1개). (2) **IMU 는 등속 크립과 정지를 원리적으로 구분 못 함**(가속도 0) — 차량 문헌(3-7, 3-10)은 정지 확정에 외부 거리/속도를 쓰고 IMU 는 전이(Δa 0.05–0.1 m/s²)·바이어스 재추정에 한정 → "카메라 절대기준, IMU 는 응답 감지·정지 보조" 를 지지. 자이로 단독 통계가 결합과 동급(3-1)이라 회전 정지는 \|ω\| 문턱(센서 바닥 0.14 °/s, 실무 0.3–3 °/s)으로 충분. (3) SETTLE: 지게차 진동 3–8 Hz(3-14) → 창 ≥0.3 s 가 물리 하한, 실무 기본 250 ms–1 s(3-13); 시간 이득은 작지만 진동 지표 이벤트로 끝내면 D_obs 정의가 "진동 아래 관측" 으로 일관됨.
- 판정 도움: **critic/judge 쪽** — IMU 역할을 응답 감지·정지 보조로 한정하고 상수는 실측 후. proposer 의 "임계+지속시간" 골격 자체는 PX4/ArduPilot 표준과 일치하므로 유지. 제3안(문헌 지지): 문턱을 config 상수로 두지 말고 **정지 로그 지표 최대값 × 여유 배율**로 실시간 도출 + 정지 확정은 카메라 v̂·위치 창(Autoware/SOS 형식), IMU 는 전이 시각(start/stop delay 측정)·바이어스 재추정.
- **emergency 0x80 의 차량측 의미: 문헌 없음** — 제조사(광운대 인터페이스) 프로토콜 고유. 레포 .md 어디에도 설명 없음; 코드상 차이는 byte0 0x42→0x80, byte1/2 가 중립 127 이 아닌 0x00, sync 카운터 미적용, 해제는 'm'→driving_mode 재진입. **실차 실험으로 결정해야**: stop(중립) vs emergency 각 5회, IMU 200 Hz 로 감속 개시 지연·최대 감속도·정지거리·해제 후 재출발 가능 여부 기록(포크 리프트 byte4 안전 확인 포함).
- **σ_a,still 문헌값 없음(전동지게차·마스트·적재 조건) — 실차 실험으로 결정해야**: 정지 상태(비적재/적재, 마스트 하강/상승, 유압 펌프 on/off) 각 30 s 에서 accel 100 Hz·gyro 200 Hz 로 PX4식 EMA\|Δa\|·std(\|a\|,0.3 s)·\|ω\| 분포와 최대값 → 크립 97 주행 30 s 의 같은 통계와 겹침 여부 확인; 겹치면 IMU 정지 판별 포기하고 카메라 v̂ 만.
