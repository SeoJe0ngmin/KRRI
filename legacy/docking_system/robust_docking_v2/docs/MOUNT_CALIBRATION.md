# 카메라 재장착 후 정면 보정

카메라를 탈부착하면 **주행 전에 한 번** 측정한다. 같은 장착 상태로 v1/v2/v3를 비교할 때는 한 결과를 함께 사용한다. 자동 IMU 초기 보정(`READY`)은 자이로 영점과 중력축 보정이며 카메라와 차체 사이 정면각 보정이 아니다.

## 현장 실행

1. 수평 바닥에 차량을 정지시키고 차체 중심선을 태그 면에 수직으로 맞춘다. 바닥 기준선/줄자 등으로 **차체**를 맞춘다. 화면 중앙에 태그가 보이는 것만으로 정렬됐다고 판단하지 않는다.
2. 태그는 평평하고 수직이어야 하며 인쇄된 윗변을 수평으로 둔다. 태그 전체가 충분히 크게 보이고 테두리가 잘리지 않는 곳에서 측정한다. 카메라와 케이블을 고정한다.
3. 다른 카메라 프로그램을 종료하고 아래 명령을 실행한다. 시작 안내에서 정렬 조건을 확인한 뒤 Enter. 준비 여유 15초와 측정 60초를 포함해 약 75초 동안 계속 정지한다.

```bash
source /home/jetson/.venvs/krri/bin/activate
cd /home/jetson/krri/docking_system/robust_docking_v2
bash scripts/run_nano.sh calibrate-mount --seconds 60 --apply-versions --view
```

CAN을 열지 않는다. 화면 포트는 8765다. `--apply`와 `--apply-versions`는 모두 상위 `docking_system/configs/common.json` 한 곳에 성공한 결과를 적용하며, v1~v4가 다음 실행에 자동 반영한다. 측정·저장만 하려면 두 옵션을 모두 생략한다. 중앙 `preflight.py mount`는 적용까지 수행한다. VM에서는 `run_vm.sh`로 실행한다.

카메라가 차체 중심선에서 벗어난 **좌우 거리**는 줄자로 별도 측정한다. 이를 함께 입력할 때만 `--camera-lateral-m 값`을 추가한다(단위 m, 왼쪽 +/오른쪽 −). 생략하면 이전 장착의 좌우 거리를 재사용하지 않고 미측정으로 둔다. 회전중심의 좌우 오프셋을 카메라의 좌우 위치로 대신 넣지 않는다. 높이·포크 앞끝 거리도 재장착 후 확인한다.

## 결과와 적용 범위

- `work/docking_system/<실행 버전>/<시각_UUID>_mount_calibration/mount_calibration.json`에 좌향 yaw, 아래쪽 pitch, roll, 회전행렬, 흔들림, 실패 사유, 카메라 일련번호와 적용 파일 목록을 저장한다. 원시 관측과 사용한 설정은 하위 `capture/`에 있다. PC 시계가 1970년이어도 UUID로 폴더 충돌을 피한다.
- 현재 검출기의 IPPE 좌표계에서 얻은 태그 회전을 사용한다. 기준 자세에서는 `R_body_camera = R_reference_tag × R_camera_tagᵀ`이다. 1초 블록마다 대표 회전을 구한 뒤 같은 비중으로 결합한다. 예전 보정각을 빼거나 기존 제어기의 좌표계를 복사하지 않는다.
- 태그 시간 커버리지, 모호한 자세 거부, 전후반 각도 변화, 위치 흔들림, IMU 준비·시간 연속성·1초 평균 회전속도를 검사한다. 진단 한계는 결과 JSON의 `limits`에 남는다. **이 조건 통과는 반복성 검사이며 실제 ±3cm 정확도 보증이 아니다.**
- 차체가 태그 면에 1도 비뚤게 서 있으면 그 각도도 장착각에 섞인다. 가만히 찍은 영상만으로 차량 오정렬, 태그 기울기, 자세에 따른 PnP 편향을 분리할 수 없다. 기준 정렬을 확인할 수 없으면 적용하지 않는다.
- 실패하거나 Ctrl+C로 취소하면 설정을 변경하지 않는다. 적용 시 같은 센서/태그 프로필인지 전부 확인한 다음 파일을 갱신한다. 다른 카메라/영상 스트림에 IR 보정값을 복사하지 않는다.
- 적용하는 것은 `R_body_camera`와 카메라 모델/일련번호다. 좌우 거리를 입력한 경우 기존 실측 높이와 함께 `T_body_camera`도 생성한다. 현장의 `R_dock_tag`, 태그 위치, 제동·오차 범위, CAN 명령은 변경하지 않는다. 기존 장착 검증 승인을 해제하며 변경 전 정책은 설정 해시가 달라 재사용되지 않는다. 나머지 주행 입력·검증을 완료한 뒤 정책을 다시 만든다.

기본 코드 업데이트는 Jetson의 기존 공통 설정을 유지한다. `--with-config`를 지정한 경우만 맥북 공통 설정으로 교체하므로 기존 현장 보정값도 교체된다는 점에 주의한다.

## 예전 실험에서 참고할 값

사용자가 확인한 최근 실험 기준은 `apriltag_v4`다. v5는 그 뒤 작성한 코드다. 이전 주행·판단·학습 로직은 이 기능으로 이식하지 않는다.

| 항목 | v4 기록 | 현재 취급 |
|---|---|---|
| 회전중심 앞뒤 | `CAM_TO_ROT_CENTER_M=-0.465` | 당시 카메라보다 앞쪽 0.465m. 재장착 후 기준 위치 확인 |
| 회전중심 좌우 | `ROT_CENTER_LATERAL_M=-0.112` | 당시 카메라보다 오른쪽 0.112m. 카메라의 차체 중심선 오프셋과 다른 값 |
| 회전중심 맞춤 잔차 | 29.3mm RMS | 과거 맞춤 통계이며 보장 최대 오차가 아님 |
| 카메라 정면각 | 1.14도 | 당시 장착의 값. 현재값으로 넣지 않고 위 명령으로 새 측정 |

출처는 `apriltag_v4/config/control.py`와 2026-10-01 주행의 `config.json` 기록이다. 회전중심은 향후 회전 모델의 참고 측정값으로 남기며, 현재 제어기에서 차체 기준점 대신 대입하지 않는다. 현재 차체 기준점은 **카메라 앞뒤 위치에 해당하는 차체 중심선의 지면점**이다. 차량 전체 길이의 중간점이나 회전축을 뜻하지 않는다.

이전 태그 검은 외곽 한 변은 0.30m이고, PDF 생성기의 권장 흰 여백은 한쪽 0.0375m다. 따라서 권장 인쇄물의 중심부터 흰 바깥끝은 0.1875m지만 실제 출력물 여백은 별도 확인해야 한다. 좌측 태그 위치 `y=+1.00m`는 사용자가 정한 임시값이며 흰 여백에서 계산한 수치가 아니다. 전후 위치와 주차 깊이는 아직 미정이다.

v4 주행 기록을 v5에서 재분석한 전진 속도 약 0.2895m/s, 등가 제동 시간 0.295초 등은 이전 CAN 전진 byte 67의 이력이다. 현재 `forward_slow` byte 97의 검증값으로 쓰지 않는다. 영상 지연·정지 흔들림·평균 제동 잔여도 현재 Jetson의 최대 오차/최대 지연 상한으로 바꾸어 넣지 않는다.
