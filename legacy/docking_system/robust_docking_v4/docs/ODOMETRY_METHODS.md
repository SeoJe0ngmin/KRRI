# 오도메트리 개선 근거와 적용 범위

이 폴더는 현재 **robust_docking_v4**이다. 아래 A/B/C는 각각 현재 v2/v3/v4에 대응하며, v1은 v4와 같은 추정 옵션을 쓰는 원본이다.

2026-10-15. D435i IR+depth, gyro/accel, Jetson을 사용하는 현재 구현에 대한 검토다. 논문의 성능 수치를 이 차량의 성능으로 사용하지 않는다.

## 결론과 이번 변경

오차는 태그가 사라진 때에만 발생하지 않는다. 태그가 보이는 중에도 상대 추적은 드리프트하고, 태그 관측에는 흔들림과 지속적인 편향이 있다. 유효한 절대 관측은 누적 오차를 제한하는 데 도움이 되지만 오차를 0으로 만들지는 않는다. 실제 오차가 매 순간 단조롭게 증가한다는 뜻도 아니다.

현재 구조는 **희소 IR-D VO + 자이로 방향 전파 + 태그 보정**이다. 태그 보정을 제한된 가중치로 적용하며, C 구성은 3축 자이로를 영상 추적의 초기 예측에도 사용한다. 완전한 VIO/EKF, 가속도 이중 적분, 진동 자동 분류, 차량 운동 모델 학습을 새로 구현한 것은 아니다.

- VO가 현재 촬영 시각까지 예측한 위치와 gyro 방향을 기준으로 태그 보정량을 정한다. 이전 영상 위치와 새 태그를 평균 내어 실제 이동을 지워 버리지 않는다.
- 태그 크기·검출 margin·재투영 오차·두 자세 해의 모호율로 보정 비중을 조절한다. 이 점수는 정확도나 확률 공분산이 아니다. 기존 모호성/추적 일치 검사를 먼저 통과해야 한다.
- 보정 후 중심이 원시 태그 위치와 달라진 만큼 오차 범위를 넓힌다. 반복 검출 횟수로 정확도가 자동 향상됐다고 계산하지 않는다.
- 시간 경과도 프레임당 오차 계산에 포함한다. 별도의 미측정 시간당 계수를 사용자에게 추가로 요구하지 않는다.
- 정지 명령은 위치·방향 적분이나 오차를 초기화하지 않는다. 제동 중 잔류 병진·회전·되튐도 관측된 만큼 계속 추적한다.

## 내일 비교 구성: 자이로 보조 영상 추적

A는 태그 직접 갱신, B는 태그 가중 보정, C는 B에 자이로로 특징점의 회전 이동을 예측하는 구성을 더한다. 현재 비교 구성은 공통 설정과 각 버전의 `version.json`으로 정하며, 별도의 A/B/C 설정 생성 명령은 사용하지 않는다. 어느 구성이 실차에서 더 나은지는 아직 확인하지 않았다. 모든 구성은 로그를 여러 번 모아 학습해야 시작하는 구조가 아니다.

C는 [RealSense SDK의 센서 간 변환](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)을 실제 gyro/활성 영상 스트림 사이에서 읽는다. SDK 회전 배열은 column-major이며, 차량 yaw축이나 임의 단위행렬로 대체하지 않는다. 중력축을 구하는 초기 IMU 보정과 이 공장 센서 간 변환은 서로 다른 정보다. 이 값이 존재한다고 실제 차량 장착·카메라/IMU 시간 오프셋까지 검증됐다는 뜻은 아니다.

A/B/C 모두 최근 책상 측정에서 READY를 확인한 초기 보정 설정을 사용한다(0.1초 창, 10초 수집, 원시 표준편차·피크와 창 평균 표준편차를 각각 검사). 주행용 기본 파일도 여기에 맞췄다. 값이 흔들린다고 원시 피크/평균 검사를 없애지 않았고, 엔진 진동에서 통과 여부는 아직 확인하지 않았다. 이 초기 보정은 실행 시작 시 한 번 하며 주행 중 계속 정지할 것을 요구하지 않는다. 별도의 정지 재보정은 기존 검증 조건을 충족할 때만 수행한다.

영상 기준 프레임과 현재 촬영 시각 사이의 gyro를 보간·3축 적분하고, 회전으로 인한 특징점 위치를 [OpenCV LK의 초기 추정](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)에 준다. 전후 방향 추적·깊이 기반 PnP·기존 품질 검사는 유지한다. 영상으로 구한 3축 회전이 자이로와 기존 일치 문턱 이상 다르면 실패로 기록한다. SDK 축 변환/보정/시간 범위가 없으면 자이로 예측은 사용하지 않고 그 이유를 남긴다. 영상 추적까지 실패한 구간을 gyro만으로 병진 이동한 것으로 만들지 않는다.

`gyro_vision_settings.json`은 SDK 축 변환과 사용 가능 여부, `odom.gyro_aid`는 프레임별 사용/실패 이유, `metrics.json`의 `gyro_aided_frames`/`gyro_rotation_rejected`는 누적 횟수다. 보류된 기준 프레임을 다시 찾을 때에는 바로 전 처리 영상이 아닌 실제 기준 프레임 시각부터 적분한다. 초기 보정/정지 재보정 경계를 가로지르는 예측은 하지 않는다.

특징점의 3×3 깊이 검사와 왜곡 보정을 배열로 묶어 처리하도록 바꿨다. 유효 깊이 개수·깊이 퍼짐·특징점 간격 등의 문턱은 동일하다. Jetson에서 FPS가 얼마 개선되는지는 재측정이 필요하다. `camera_odometry`는 장착 변환 없이도 상대 추적을 진단하기 위한 카메라 좌표이며 차량 위치로 사용하지 않는다.

## 오차를 계산하는 방식

VO 구간에서 축별 기본 오차를 다음과 같이 계산한다. x/y는 m, yaw는 rad다.

```text
E = E_anchor
    + k_distance × 누적 이동거리
    + k_rotation × 누적 절대 회전량
    + k_frame × max(처리 프레임 수, 기준 이후 경과시간 × 설정 FPS)
```

기존 `odom_error_per_m`, `odom_error_per_rad`, `odom_error_per_frame`, `camera.fps`를 사용한다. 마지막 항은 처리 누락이 있는 동안에도 기존 프레임 오차 예산을 소모한다. 독립된 시간 드리프트 계수를 새로 알아낸다는 뜻은 아니다. 프레임당 범위가 해당 FPS·진동·장면·운동 조건을 덮는지 검증해야 하며, 모르는 범위는 null로 남는다. gyro 방향은 기존 `gyro_rate_error_rps × dt`로 오차를 전파한다. 방향 오차가 이동거리와 카메라 레버암을 통해 만드는 위치 오차도 추가한다.

원시 태그 관측을 `z`, 그 오차 반경을 `e_tag`, 보정된 중심을 `x`라고 하면 다음을 적용한다.

```text
새 기준 오차 = e_tag + abs(z - x)
```

각도는 같은 회전 구간으로 펼쳐 계산한다. 이 구간은 원시 태그의 전체 오차 구간을 포함한다. **원시 태그의 오차 범위 자체가 실제를 포함한다는 조건**이 필요하다. 태그 크기 오입력·장착 편향·잘못된 해를 이 식이 고치는 것은 아니다. 보정으로 생긴 잔차는 커질 수 있고, 제어기는 그 범위가 커지면 기존 규칙대로 정지한다.

상대 추적의 좌표계와 누적 오차는 태그 보정만으로 초기화하지 않는다. 추적이 끊겨 새 좌표계가 생기면 이전의 정밀 위치를 그대로 이어 붙이지 않는다. 검증된 속도 상한으로 짧은 구간을 연결하는 기존 복구는 별도이며 정확도는 낮아진다.

## 사용자가 입력하는 값과 자동 처리하는 값

| 구분 | 값 | 현재 상태 |
|---|---|---|
| 직접 알아야 하는 기하 | 차폭/앞뒤 길이, 통로/목표, 태그 크기/위치, 카메라 장착 | 실제 설치값 필요. 로그 평균으로 대체 불가 |
| 장치에서 읽는 값 | 영상 내부 파라미터, 촬영·IMU 시각, 지원 스트림 | SDK에서 읽고 기록 |
| 실행 중 측정하는 값 | 정지 초기 gyro bias/중력 방향, 특징점 이동, 태그 관측 품질 | 기존 보정/추적 및 이번 가중치에 사용 |
| 실제 움직임으로 검증하는 값 | 영상 오차 범위, 최대 속도, 제동 지연·잔여 이동/회전, 되튐 | 정지 로그만으로 알 수 없음. 기존 실차 검증 항목 유지 |
| 알고리즘 설정 | 태그 최대 보정 비중 | 초기값 `[0.5, 0.5, 0.5]`. 조정 가능한 설계값이며 물리 실측값·정확도 보증값 아님 |

이번 변경으로 **필수 물리 실측 항목은 추가하지 않았다.** 과거 여러 run의 학습 파일도 요구하지 않는다. 다만 기존 실차 설정에 미입력 항목이 많다는 문제까지 없어졌다고 할 수는 없다. 추후 자동 측정 도구는 관측 가능한 값만 채우고, 실제 제동·절대 위치 오차까지 데이터 없이 추정해서 채우면 안 된다. 실행 중 재보정도 위치 오차를 초기화하지 않고 이후 사용할 bias만 수정한다.

## 진동·관성·되튐의 구분과 다음 측정

구동계 진동은 센서 잡음뿐 아니라 카메라의 실제 움직임과 영상 흐림을 만들 수 있다. 반면 관성과 되튐은 차량의 실제 운동이다. 평활화로 전부 제거하면 제동 중 움직임까지 놓친다. 정지할 때만 관측하면 STOP 이후의 이동, 공간 이탈, 목표 통과 시점을 놓칠 수 있으므로 이동·제동 중에도 계속 추적해야 한다.

CAN 없는 `measure --view`로 실제 장착 상태에서 다음 조건을 나누어 기록한다.

1. 구동계 OFF 정지 / ON 정지: 초기 보정 성공, gyro 원시값과 영상의 흔들림 비교.
2. 기존 수동 조작으로 저속 직진·정지 / 좌우 회전·정지: 잔류 이동·회전·되튐을 계속 관측하는지 확인.
3. 태그가 계속 보이는 경우 / 태그만 가리는 경우 / 배경 추적까지 잃는 경우를 구분.
4. 눈금·알려진 위치/각도 같은 별도 기준과 비교. 같은 태그 관측을 정답으로 놓고 태그 융합의 절대 정확도를 평가하지 않음.
5. 원시 태그, 보정 위치, 오차 범위, 실제 기준값을 함께 비교하고 그 뒤 실차 범위를 정함.

현재 실차 설정의 장착 변환이 null이면 절대 `pose`도 null이며 이번 태그 보정은 시작되지 않는다. 태그 검출 및 카메라 기준 원시 위치와 IMU/VO 진단은 가능하다. 설정 변경 후 정책은 다시 생성해야 한다.

## AprilGrid 선택

AprilGrid는 여러 AprilTag의 배치를 알고 쓰는 보드다. [Kalibr](https://github.com/ethz-asl/kalibr/wiki/calibration-targets)는 일부 가려진 보드도 사용하는 보정 대상으로 소개한다. [OpenCV 보드 문서](https://docs.opencv.org/4.x/db/da9/tutorial_aruco_board_detection.html)는 알려진 여러 마커의 모서리를 함께 사용해 보드 자세를 구하는 원리를 설명한다.

사용자는 보드를 크게 만들기 어렵다고 했다. 같은 전체 면적에 작은 태그를 여러 개 넣으면 개별 태그의 원거리 식별이 불리해질 수 있으므로 **이번에는 기존 큰 단일 태그를 유지**한다. 가까이에서 충분한 모서리가 보일 때의 그리드 이점과 원거리 검출을 실제 해상도·거리에서 비교한 뒤 결정할 사항이다. 보드 전체가 안 보이면 그리드 역시 절대 기준을 주지 못한다.

현재 코드는 목표 ID 하나를 사용한다. 여러 태그를 붙이기만 해서는 공동 자세 추정으로 바뀌지 않는다. 도입 시 보드 배치/실제 인쇄 크기·평탄도를 확인하고, 여러 ID의 모서리를 하나의 좌표계로 변환해 공동 자세를 구해야 한다. 작은/먼 평면 보드의 모호성이 항상 사라진다고 보장하지 않는다.
