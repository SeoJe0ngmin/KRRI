# 구현 상세

현재 공통 설정·실행 방법은 [상위 run.md](../../run.md)를 따른다.

## 방법론과 구현 범위

상세 수식·전제는 [METHOD.md](docs/METHOD.md), 설정 방법은 [CONFIGURATION.md](docs/CONFIGURATION.md)를 보십시오.

| 규칙 | 구현 |
|---|---|
| R0 출발 자격 | 설정/센서 보정/오차 근거, 차체 전체의 자유공간 포함, 정지 관측, 정책 영역 확인 |
| R1 상태 범위 | 태그 절대 기준 + 희소 깊이 특징점 이동량 + IMU 상대 yaw, 거리/회전/프레임 수에 따른 오차 증가 |
| R2 다음 정지 위치 | 전진 길이/후진/회전 후보에서 현재 관측 셀에 맞는 정지 영역을 매번 다시 선택 |
| R3 이동 중 안전 | 차량 사각형 전체, 방향 오차, 지연·관성·미끄러짐을 포함한 이동/정지 포락선 검사 |
| R4 목표 도달 가능성 | 가능한 **모든 후속 관측 셀**이 더 낮은 도달 단계로 가는 동작만 채택하는 AND-OR 역방향 합성 |
| R5 주행 중 피드백 | 직진 중 위치, 회전 중 태그에 기준을 둔 IMU yaw로 정지 여유 전부터 제동. 실시간 관측 지속 |
| R6 정지 후 재계획 | 실제 정지 확인 후 재측정·자동 복구. 서로 다른 새 관측의 유지 시간과 개수, 더 엄격한 재출발 오차 기준 적용. CAN/사용자 정지 잠금은 자동 해제하지 않음 |
| R7 완료 | 상태 범위 전체가 목표 위치/방향 안에 있고 정지 관측 유지까지 충족 |

기존의 “적응형 point 생성” 개념은 **다음 정지 영역을 반복해서 고르는 방식**으로 포함했습니다. v5의 기록 학습/시간 기반 최종 눈감기 로직을 그대로 옮기지는 않았습니다.

콘 진입은 일반 접근을 먼저 검사합니다. 일반 접근이 없고 횡오차 구간 전체가 문턱 밖일 때만 `SIDESTEP`으로 입구 밖에서 정렬합니다. 정렬 후 일반 접근으로 이어지는 상태만 종료점으로 인정하며, 매 정지마다 다음 동작을 다시 선택합니다. 태그 화각·최소 픽셀 크기 또는 현장에서 확인한 추적 구역도 경로 조건에 포함합니다. 장면의 무늬/가림까지 미래에 보장하는 기능은 아닙니다.

명령 지연은 **출발 관측까지의 대기, 출발 관측 후 동작, STOP 응답, 정지 확인**으로 분리했습니다. 실차의 명령/관측 지연과 CAN 명령 갱신 허용 시간은 측정 전 `null`입니다. 기존 8초/15초를 실차 동작의 고정 상한으로 복사하지 않았습니다. 상세 항목은 `docs/CONFIGURATION.md`에 있습니다.

회전 제동은 IMU 콜백이 별도 공유 메모리로 전달하는 최신 누적 각도를 사용합니다. 주 제어 루프가 영상 프레임 도착과 무관하게 검사하며, 일반 회전·태그 복귀 회전과 최초 탐색의 각도 제한에 적용합니다. 이미지 촬영 시각의 IMU 각도를 보간해 연결하므로 영상 처리 완료 시각을 촬영 시각으로 대체하지 않습니다. 실차 루프는 10 ms sleep을 사용하지만 100 Hz 실행을 보장하지 않으며, 호스트 스케줄링·USB·CAN 지연은 실측 제동 여유와 watchdog 설정에 포함해야 합니다. 오래된 영상으로 위치 안전성을 계속 인정하는 기능은 아닙니다.

정지 판정에도 매 제어 주기의 최신 자이로를 적용합니다. 같은 영상이 반복되어도 새 자이로가 회전·누락·만료를 나타내면 정지 유지 시간을 취소합니다. 초기 출발, 재출발, 최종 완료에 같은 검사를 쓰며, 병진 정지에 필요한 영상 근거는 유지합니다. 자이로 샘플의 수신 후 경과 시간도 검증된 각가속도 상한으로 반영합니다.

출발 위치 범위 일부가 이미 제동 기준 안에 있는 동작은 계획에서 제외합니다. 실제 움직임이 확인되기 전에 제동 기준에 도달한 경우 정상 동작 완료로 처리하지 않고 STOP·재관측합니다. 현재 계획 알고리즘 버전은 `observation-game-recovery-v4`이므로 이전 버전에서 저장한 정책은 같은 설정이라도 `synthesize`로 다시 생성해야 합니다.

태그가 잘려도 바닥/배경의 고정 특징점과 유효 깊이가 계속 보이면 상대 이동을 이어 갑니다. 특징점·깊이·IMU 정합이 사라지면 추정 좌표를 계속 만들어내지 않습니다. 탑재부 내부가 비어 있거나 장면이 무늬 없이 보이면 이 조건이 충족되지 않을 수 있습니다. **카메라·IMU만으로 어떤 환경에서도 3 cm 여유 진입을 보장한다는 구현은 아닙니다.**

이번 구현은 2D 평면 도킹과 알려진 자유 직사각형 영역을 대상으로 합니다. 센서 오차 상한과 운동 동작 범위가 실제로 맞고 관측이 유지되는 조건에서의 유한 추상 모델을 검사합니다. 일반적인 3D 지형, 움직이는 장애물 인식/회피, 전체 SLAM, VINS의 최적화기를 구현한 것은 아닙니다. 경사·롤·회전중심 변화의 영향도 설정 범위에 포함되지 않으면 적용 대상 밖입니다.

## 최초 태그 탐색과 출발

실차 프로필에는 최초 한 번만 실행하는 `startup_search`가 있다. Enter 이전에는 움직이지 않는다. 시작 자이로 보정·센서 준비·실제 정지를 확인한 뒤, 목표 태그가 보이면 탐색을 건너뛰고 정지 재측정한다. 태그가 없는 것을 여러 새 검출 시도로 확인하면 설정 방향으로 제자리 회전한다. 기본은 좌회전이며 90° 고정 회전이 아니다. 최대 한 바퀴 예산 안에서 정지 여유를 남기며, 태그 ID를 검출한 순간 STOP을 요청한다. 자세가 모호한 검출도 정지 사유지만 출발 위치 확정에는 사용하지 않는다.

정지 후 새로 수락된 태그 관측 여러 개, 안정 시간, 위치·각도 오차 조건을 충족해야 일반 주행 판단으로 넘어간다. 적격 정지 자이로 재보정이 진행 중이면 완료를 기다린다. `startup_search.improvement`가 활성화되면 초기 획득 중의 가장자리 잘림·제동 후 태그 재소실에 한해 기존 각도·시간·이동 예산 안에서 관측 개선과 재탐색을 시도한다. 작은 태그나 모호한 자세를 임의 수락하지 않으며, 제한 내 회복하지 못하면 종료한다. 일반 주행 중 태그 소실로 최초 탐색을 다시 시작하지 않는다.

태그를 처음 보기 전에는 탑재부 기준 위치를 모르므로, 출발 위치 주변에 차량 전체 회전·병진 편차·제동 여유가 들어가는 자유공간을 별도로 확인해야 한다. 탐색 중에도 영상 상대 이동과 IMU를 감시하며 연결 소실이나 각도/시간/병진 한계 초과 시 STOP·FAULT로 끝난다. 필요한 실측 항목은 아직 `null`이며 이 상태에서는 실차 실행이 열리지 않는다. 최초 탐색 완료 후 주행/사이드스텝에서 태그가 사라지는 상황은 아래 복구 절차로만 처리한다.

## 일시정지·자이로 재보정·태그 복귀

실차 프로필의 `recovery`를 사용하면 일시적인 관측 끊김/오차 증가를 `PAUSING → REOBSERVING → 재계획`으로 처리합니다. 전체 실행 시간·동작 수·복구 횟수를 초기화하지 않으며, 중단한 명령의 남은 시간을 재생하지 않습니다. 현재의 새 관측 범위가 정책에 포함되어야 다시 움직입니다. 정상 동작의 도달 증명을 중간 정지/복구 자체에까지 확대해서 주장하지 않습니다.

사이드스텝은 **옆으로 회전 → 옆 이동 → 태그 쪽 복귀 → 정지 재측정**으로 운영합니다. 옆 이동 완료 또는 추적 저하로 중단되면 태그를 다시 보는 복귀를 우선합니다. 회전하자마자 태그가 사라졌다는 이유로 옆 이동 전에 즉시 되돌아오지는 않습니다. 태그만 없는 동안 배경 추적이 유효하면 기존의 고정 10초 소실 제한으로 중단하지 않습니다.

짧은 특징점 추적 실패에는 제한된 시간 동안 기존 기준 영상을 보존합니다. 같은 움직임의 검사된 이동·STOP 범위 안이고 제동점에서 충분히 멀 때만 현재 명령을 잠시 유지합니다. 예측 위치를 실제 이동 관측으로 세거나 새 전진 명령을 시작하지 않습니다. 재추적이 새 좌표에서 시작되면 끊긴 동안의 최대 이동량을 오차에 포함한 **거친 위치 범위**로 연결하며, 이를 정밀 위치 복구로 표시하지 않습니다.

배경 추적까지 사라져도 `recovery.blind_return`에 실차 검증 근거가 있으면 복귀 회전을 시도할 수 있습니다. 마지막 관측과 이미 검사한 동작·STOP의 전체 위치 범위, 연속 자이로, 실측한 STOP 후 정지 상한을 사용합니다. 정밀 도킹용 위치 문턱은 복귀 회전에 적용하지 않으며, 차체 전체 회전 공간·방향 오차·동작 계약은 검사합니다. 각 사이드스텝 동작 전에 복귀 공간도 확보합니다. 약 90°를 돌아 나갔다면 반대 회전 후보를 사용하되, 측면 이동 후 태그 방향을 다시 계산하며 필요하면 기존 태그 관측 방향으로 먼저 복원합니다. 후보는 검증된 `actions`에서만 선택합니다.

태그를 다시 찾는 복귀 회전에서는 목표 ID가 보이면 먼저 STOP하고 재측정합니다. 한 번 보인 태그가 다시 사라지면 짧은 관측 대기 뒤 남은 시간·횟수·공간 범위 안에서 복귀 후보를 다시 선택합니다. 한 장의 관측으로 일반 주행을 재개하지 않으며, 태그가 계속 보이는 정상 방향 보정이나 옆으로 돌아 나가는 동작에는 이 조기 STOP을 적용하지 않습니다. 복귀 전용 STOP 시간 근거는 배경 특징점의 재생성만으로 초기화하지 않습니다. 영상 정지 근거와는 구분하며, 일반 전후진·최종 완료·자이로 재보정의 근거로 대체하지 않습니다.

배경 영상의 회전과 자이로 회전을 비교할 때는 같은 두 촬영 시각을 사용합니다. 기준 영상을 유지하면 그 시각의 자이로도 유지하고, 기준 영상을 버리거나 새로 만들면 자이로 비교 기준도 함께 교체합니다. 누적 heading이나 위치 오차 범위를 0으로 리셋하는 기능은 아닙니다.

이 경로는 **복귀 회전 전용**입니다. 시각 정지 확인이 없을 때 쓰는 STOP 상한은 영상 측정이나 자이로 영점 보정의 근거로 위장하지 않습니다. 자이로가 끊겼거나 공간·동작 범위가 부족하면 정지합니다. 복귀 후에는 새 태그 여러 장과 정지 관측을 확보해야 전진을 재계획할 수 있습니다. 태그 쪽으로 돌아왔다는 사실만으로 재출발하거나 완료를 선언하지 않습니다. 복귀 회전의 종료 범위도 자이로 오차를 포함해 넓게 검사하며, STOP했다고 방향 오차를 작게 초기화하지 않습니다. 전체·동작·복구 시간 및 횟수 제한도 유지합니다.

목표 기준 위치 없이 새 상대 추적만 가능한 경우에는 정지를 확인하고 `REOBSERVING`에서 기다릴 수 있습니다. 측정 또는 검증된 복귀 조건을 충족하지 못하면 제한 시간 후 종료합니다. 반복 영상, 관측 간격 초과, 추적 기준 변경은 정지 유지 시간으로 누적하지 않습니다.

정지 중 gyro 재보정은 신선한 중립 명령, 영상 이동량·영상 회전량·IMU 상태가 함께 정지를 지지하는 구간에서만 시행합니다. 영점만 갱신하고 누적 yaw/좌표/오차 상한은 초기화하지 않습니다. `sensor.imu.stationary_recalibration`의 장비별 오차/문턱 검증 전에는 재보정을 적용하지 않으며 화면에 이유를 표시합니다. 시작 영점 보정은 별도로 유지됩니다.

설정 숫자와 실제 장비에서 확인할 항목은 [CONFIGURATION.md](docs/CONFIGURATION.md)의 복구 절, 시험 절차는 [VALIDATION.md](docs/VALIDATION.md)를 참고하십시오. 기존 정책은 설정 hash가 달라지므로 수정한 실차 설정으로 다시 생성해야 합니다.

## Nano 계산량과 의존성

기본 측정 프로필은 **IR+depth 640×480, 30 FPS 요청**, 특징점 최대 120개, 태그 검사 간격 0.15초, 화면 전송 최대 5 FPS입니다. 2026-10-11 사용자 선택에 따라, 깊이를 사용하는 현재 방식에서는 IR을 유지합니다. 태그 자세 계산 자체는 영상과 태그 크기를 사용하고, 깊이는 주변 특징점의 3차원 위치를 구해 태그 소실 전후의 상대 이동량을 추적하는 데 사용합니다.

IR 사용과 해상도 선택은 별개입니다. 640×480은 **측정용 초기 선택**이며 Nano 성능이나 정확도를 실측해 확정한 값이 아닙니다. v5의 컬러 1920×1080과 비교해 필요한 거리에서 태그 검출과 깊이 특징점 추적이 가능한지 확인해야 합니다. 깊이가 반드시 IR 영상만과 함께 쓰이는 것은 아니며, 코드는 컬러 영상에 깊이를 정렬하는 경로도 갖고 있습니다. 현재는 영상과 깊이에 같은 해상도를 요청하므로, 컬러 1920×1080 설정을 그대로 복사하지 말고 각 스트림의 지원 프로필을 확인해야 합니다.

정지 판단에는 인접 프레임뿐 아니라 일정 시간 떨어진 기준 영상과 현재 영상을 직접 비교합니다. 영상 한 장당 추가 희소 매칭 최대 1회, 기준 영상 최대 16장으로 제한합니다. 이 추가 비용의 Nano 실측은 남아 있습니다.

영상 버퍼는 최신 1개만 유지합니다. IMU는 영상처럼 건너뛰지 않고 모든 수신 샘플을 적분하며 누락을 기록합니다. 태그 ROI를 쓰되 주기적으로 전체 화면을 다시 검사합니다. 로그는 별도 스레드의 유한 큐로 넘기며 생산자는 저장을 기다리지 않습니다. JPEG, Python 스케줄링, USB 등 남은 지연은 측정해야 하며 제어와 CAN 감시 프로세스가 지연을 검사합니다. 동영상 녹화·전체 SLAM·신경망·GPU 전제는 없습니다.

| 실행 | 의존성 |
|---|---|
| 정책 합성·핵심 테스트 | Python 표준 라이브러리만 |
| 카메라·화면 | NumPy, OpenCV, pupil-apriltags, pyrealsense2 |
| 실차 주행 | 위 항목 + Kvaser 시스템 드라이버/SDK와 Python canlib |

Python 코드는 3.6 문법까지 검사했으며, 영상 의존성을 포함한 로컬 실행 검증은 Python 3.12에서 했습니다. **Nano의 Python/JetPack/카메라 SDK 조합은 아직 검증하지 않았습니다.** `doctor`로 import 여부를 확인하십시오. OpenCV에는 `solvePnPGeneric`, `SOLVEPNP_IPPE_SQUARE`가 필요합니다. Nano에 이미 있는 JetPack OpenCV/NumPy를 무작정 최신 pip 패키지로 덮어쓰지 말고 그 환경에 맞춰 의존성을 구성하십시오. 원래 저장소의 최신 버전 고정 requirements는 가져오지 않았습니다.

일반 Nano와 Orin Nano는 다릅니다. [NVIDIA FAQ](https://developer.nvidia.com/embedded/faq)에서 모델별 JetPack 지원을 확인한 뒤 SDK를 맞추어야 합니다. RealSense/CAN 드라이버 설치나 Nano OS 변경은 이 작업에서 수행하지 않았습니다.

## PC에서 코드 검증

각 버전 폴더에서 `python3 -m unittest discover -s tests`를 실행한다. 테스트용 가상 치수와 오차는 `tests/fixtures`에만 있으며 실차 측정값이 아니다. 현장용 정책은 준비한 실제 설정을 `synthesize --config`로 지정해 생성한다. 실행 순서는 [공통 현장 명령](../../run.md)을 따른다.

기록한 관측을 제어기에 다시 입력할 수 있습니다. 재생도 CAN을 열지 않습니다.

```bash
python3 -m docking replay ../../work/docking_system/robust_docking_v1/측정세션/observations.jsonl \
  --config configs/hardware.json --policy ../../work/docking_system/robust_docking_v1/hardware_policy.json
```

## 저장되는 측정 결과

`krri/work/날짜_시각_모드/` 아래에 저장됩니다. 코드 폴더의 형제 경로이며 현재 작업 디렉터리와 무관합니다. 명시적인 `--output`은 지정한 경로를 그대로 사용합니다.

- `observations.jsonl`: 장치 시각, host 도착 시각, 검출/거부 사유, 추적량, 오차 범위, IMU, 처리율. 원본 영상/깊이 파일은 기본 저장하지 않습니다.
- `metrics.json`: 단계별 처리 시간 p50/p95/p99/최대, 처리 간격, 누락, CPU 사용률(100%가 CPU 한 코어), 최대 RSS. 분위수는 최근 최대 20,000개 표본 기준입니다.
- `control.jsonl`: 제어 상태/명령 판단. 측정 모드에서는 비어 있을 수 있습니다.
- `config_used.json`, `session.json`: 사용 설정과 종료 상태.
- `camera_settings.json`: 선택 센서의 노출 요청값, 시작 시 SDK 읽기값·범위·단위. 프레임별 노출은 지원할 때 `observations.jsonl`의 `camera.frame_metadata`에 기록됩니다.
- `timestamp_settings.json`: 스트림 시작 전에 선택 센서의 `global_time_enabled`를 끈 설정과 읽기값. 영상·자이로·가속도계는 같은 D435i의 장치 시각을 사용하고, 실제 프레임의 시각 기준은 `observations.jsonl` 및 `metrics.json`의 `timestamp_domains`에 기록합니다. 다른 기준의 IMU 표본은 보정·적분에 넣지 않으며, 시각 이상 뒤 자동으로 보정 완료 상태를 복구하지 않습니다.
- `camera_model.json`: 실제 선택 스트림의 내부 파라미터·왜곡 계수·해상도. 가시성 검사 설정을 작성할 때 사용합니다.
- `imu_calibration.json`: 시작 시 정지 구간으로 구한 gyro bias와 중력 방향. 좌우 회전 부호 검증을 대신하지 않습니다.
- `metrics.json`의 `imu`: 종료 시점까지의 수신·초기 보정 상태. 영상 FPS가 정상이어도 `ready=false`이면 IMU 보정이 완료된 것이 아닙니다.
- `metrics.json`의 `tag_position_window`: 정지시켜 둔 태그의 최근 창 평균/표준편차. 거리별 바이어스나 최악 오차를 인증하지 않습니다.

기본 큐는 4,096개, flush는 처리 프레임 수와 무관하게 1초마다 수행합니다. 관측/제어 기록기는 각각 누적 쓰기량 500 MiB 상한을 가지므로 전체 세션 단일 500 MiB 제한은 아닙니다. 큐가 차면 새 기록을 버리고, 저장 실패/용량 초과는 기록 상태에 표시합니다. 이 사유만으로 주행 제어를 종료하지 않습니다. 종료 시 기록 대기는 제한되며 미저장분이 남을 수 있습니다.

카메라의 전송 지연 상한이 미측정이면 실제 촬영부터의 age 상한은 `null`입니다. host 도착 이후 경과를 전체 센서 지연이라고 표시하지 않습니다. 측정 로그는 오차/지연의 후보 범위를 조사하는 자료이지, 유한 실험만으로 물리적 최대 오차를 증명하는 인증서가 아닙니다.

## 소스 구성

```text
docking/core.py        구간 기하 / 동작 포락선 / AND-OR 정책 생성·검사
docking/controller.py  주행·제동·정지 확인·완료 / 고장 잠금
docking/startup.py     최초 한 번의 태그 탐색 / 발견 즉시 제동 / 정지 재측정
docking/vision.py      AprilTag 두 해 검사 / 희소 깊이 PnP 이동량 / IMU 결합
docking/camera.py      RealSense / 최신 영상 버퍼 / 성능 측정
docking/exposure.py    선택 센서 자동·수동 노출 / 단위·범위·적용 확인
docking/configuration.py 실측 치수 / 기준점 / 장착 변환 구성·검증
docking/calibration.py IMU 시작 정지 보정 / 실제 시각·샘플 수 검사
docking/diagnostics.py 정지 태그 흔들림 진단 / 센서 옵션 검사
docking/mission.py     일반 접근 우선 / 조건부 사이드스텝 / 단계 연결
docking/visibility.py 태그 화각·크기 / 근거가 있는 상대 추적 구역
docking/profiles.py   현장 병합 / 벽 앞 정지·콘 진입 목표 / 미입력 검사
docking/recording.py  유한 비동기 큐 / 시간 기준 flush / 저장 실패 격리
docking/canbus.py      제한된 Kvaser CAN 명령 / 독립 감시 프로세스
docking/runtime.py     SSH 터미널 / 실행 감독
docking/webview.py     브라우저 영상·평면도 / 읽기 전용 서버
configs/              측정용, 가상 데모, 미측정 실차 설정
scripts/run_vm.sh     기존 Ubuntu VM의 krri Python 환경으로 실행
scripts/run_nano.sh   Jetson Linux에서 실행
.vscode/tasks.json    원격 VS Code의 환경 확인/측정 작업
tests/                하드웨어를 열지 않는 검사
```
