- 조건부 사이드스텝 데모: 19,575개 관측 셀에서 일반 접근 1,750개, 정렬 정책 4,535개. 정렬 상태 수에는 종료점도 포함하며, 횡오차 문턱/일반 접근 우선/동작 횟수 조건을 적용한 실제 출발 가능 상태 수와 다르다.
- 조건부 정책의 **1,000회 가상 실행**, 최대 전체 8개 동작에서 목표 도달 확인. 이 예제도 작은 가상 몸체/가상 오차이며 실차 치수가 아니다. 별도로 제어기에서 회전 → 비스듬한 전진 → 방향 복원 → 일반 접근 → 최종 정지 흐름 확인.
- 일반 접근 우선, 작은 횡오차에서 사전 정렬 미사용, 정렬 중 입구 진입 금지, 잘못된 정렬 종료점/정책 변조 거부 검사.
- 태그 앞면/화각/최소 크기, 90도 회전 중 태그 이탈, 별도 근거 없는 상대 추적 영역 거부를 순수 기하 조건으로 검사. 실제 영상 검출 시험과 구분한다.
- IMU 정지 보정에서 실제 시각/유일 샘플 수, 움직임 중 재수집, 가속도 누락, 축/중력 불일치, 보정 후 bias 적분, 첫 유효 IMU 구간 대기 검사.
- 지연된 출발이 이동 후 시간 예산을 소모하지 않는지, 이동 관측 후 시간 제한, STOP 응답 예산, 새 프레임이 없거나 반복돼도 전체/동작/정렬 제한이 작동하는지 검사.
- 기록 큐 포화 시 생산자 비차단, 시간 기준 flush, 용량 초과/저장 오류의 표시와 제어 분리 검사. 실제 Nano 저장 장치 성능 시험은 아니다.
- 차량 앞끝 기준 벽 0.50 m 목표, 콘 목표의 전체 차량 진입/뒤 모서리 회전 여유, 현장/플랫폼 설정 분리, 미완성 새 시험의 승인 해제 검사.
- 깊이 없는 측정 옵션이 컬러로 전환하고 IR 보정을 비활성화하는지, odometry만 끈 비교는 depth를 유지하는지 장치 생성 전에 검사.

## 남은 장비 검증

RealSense IR/depth alignment와 동시 IMU 수신, 노출 제어·프레임 metadata, pupil-apriltags native 라이브러리, Kvaser 연결, 브라우저 실영상, Nano 처리량은 해당 장비 환경에서 확인해야 한다. NumPy/OpenCV 기반 영상 단위 검사는 아래 2026-10-11 실행에서 건너뜀 없이 통과했다. Nano 실제 성능이나 3 cm 진입 정확도를 이 검사로 입증하지 않았다. 통로 중심선 사전 정렬과 태그 화각/크기·현장 추적 구역 검사는 구현하고 가상 조건에서 검사했다. 실제 장면의 미래 가림/특징점 존재를 증명한 것은 아니다.

각 단계별 실행 방법은 README에 있다. 센서 측정은 현장 기하/운동 계약이 미확정이어도 실행 가능하고, 실제 CAN 주행은 별도 실차 설정 검증 후 가능하다.


## 실행 범위의 한계

기존 영상 테스트 6개는 SE(3) 변환, 태그 ROI 좌표 복원, 최소 태그 크기 거부, 동일한 두 PnP 해의 모호성 거부, 깊이 미확보 시 추적 해제, KLT 반환 누락 시 추적 해제를 다룬다. 최초 Python 3.13 환경에서는 의존성 부재로 건너뛰었지만, 이후 Python 3.12/NumPy/OpenCV 환경에서 실행해 통과했다. 실제 SDK의 두 파이프라인·노출 제어·IR/depth 정렬 및 컬러 무깊이 수신은 카메라 연결 후 확인할 항목이다.

## 최초 태그 탐색 검증

2026-10-11 초기 탐색 추가 후 Python 3.12.7 / NumPy 1.26.4 / OpenCV 4.10.0에서 전체 **133개 테스트 통과, 건너뜀 없음**. 그 뒤 초기 탐색에서 실제 계획기를 거쳐 최종 정지까지 이어지는 통합 검사 1개를 추가해 별도로 통과했다. 서로 다른 총 134개 검사이며 134개를 한 번에 재실행했다는 뜻은 아니다.

- 처음부터 태그가 보이면 회전 생략, 태그가 뒤에 있으면 좌/우 탐색으로 약 180° 회전 후 STOP·정지 재측정.
- 목표 ID를 읽었지만 자세가 모호한 경우에도 STOP. 다른 ID나 검출 미실행 프레임으로 발견/부재를 확정하지 않음.
- 당시에는 제동 중 태그 소실 시 재탐색하지 않았다. 현재는 최초 획득 단계 안에서만 제한된 재탐색을 허용한다. 반복 프레임/한 장/오래된 기준만으로 출발 금지는 유지한다.
- 센서 지연·추적 재생성·시계 역행·각도/병진/시간 예산 초과에서 STOP·FAULT 유지.
- 최초 획득 완료 후 일반 주행의 태그 잘림은 초기 탐색을 재개하지 않으며, 사이드스텝 소실은 기존 복구 절차로 처리.
- 절대 태그 위치가 없을 때의 차체 상대 이동 변환/오차 증가 검사. 상대 위치만으로 절대 위치가 유효하다고 표시하지 않음.

실차에서는 출발 주변 회전 공간, 실제 회전 중 기준점 병진 편차, 출발 지연·제동 회전량, 회전 중 영상 추적을 확인해야 한다. 손으로 카메라를 돌리는 시험은 차량 운동 범위 측정을 대신하지 않는다.

실차 제어 지연/관성, 주행 중/태그 소실 후 정확도, 속도 상한으로 실제 정지 확인이 가능한지, 3 cm 통로 진입 성능은 미검증이다. 검사 결과는 코드와 가상 범위의 동작에 관한 것이며 실차에 `validation.approved=true`를 설정할 근거를 대신하지 않는다. `configs/hardware*.json`은 미측정 수치와 검증 근거가 비어 있어 CAN 주행이 열리지 않는다.

## 자동 복구와 정지 자이로 보정 시험

먼저 CAN 없는 measure/shadow로 진행한다. 설정의 미측정 값을 데모 값으로 채우거나 검증 flag만 올려 실차 실행하지 않는다.

1. 카메라를 고정하고 시작 보정 전후와 장시간 정지 gyro drift를 기록한다. 영상 상대 이동/회전 오차, 정지 시 변동·샘플 gap을 확인한 뒤 stationary_recalibration의 문턱과 바이어스 변경 상한을 정한다. 적용 전후 yaw가 0으로 점프하지 않는지와 오차 상한이 임의로 작아지지 않는지 확인한다.
2. 태그만 가리고 배경 특징점은 남긴다. 절대 기준 추적이 유지될 때 즉시 FAULT가 되지 않는지 확인한다. 태그와 특징점 추적까지 끊었다가 새 특징점만 제공했을 때 위치가 복구됐다고 표시하지 않아야 한다.
3. 일시 관측 저하 후 태그를 다시 보여 준다. 정지 유지, 서로 다른 태그 관측, 충분한 새 영상 시간/개수, 더 엄격한 오차 조건을 통과해야 다음 동작을 계획한다. 태그 한 장/반복 프레임만으로 재출발하면 실패다.
4. 회전 중 태그 소실, 좌우 90° 복귀, 프레임 저하, 화면 일부에 차량 부품이 크게 보이는 경우를 따로 측정한다. 방향을 포함한 실제 추적 영역과 돌아보는 회전 전체의 차량 공간을 확인한다. 카메라를 손으로 돌린 시험은 CAN 회전 지연·관성 계약을 대신하지 않는다.
5. 실차에서는 STOP 후 미끄러짐/출발 지연을 포함해 회복 시간을 검증한다. 120초 회복 예산보다 동작별 STOP 응답·정지 확인 상한이 먼저 적용될 수 있다. 반복 실패 시 횟수·전역 시간으로 종료되는지, 사용자 정지와 CAN lease 실패가 자동 해제되지 않는지 확인한다.
6. 변경 전후 CAN 캡처를 대조한다: 0x1E3 data[1]/data[2]만 주행, 나머지 127; 0x2E3 주행 모드 0x0A와 sync counter; 0x764 [0]. 자동 복귀 역시 동일한 제자리 회전 프레임이어야 한다.

2026-10-11 소프트웨어 검증: Python 3.12 / NumPy 1.26.4 / OpenCV 4.10.0에서 `python -m unittest discover -s tests -v` **116개 통과, 건너뜀 없음**. 실제 계획기를 연결한 사이드스텝 중단 → 복귀 회전 → 태그 재검출 → 최종 정지, 좌/우 90° 복귀, 중복 영상·재검출 한 장·잔류 운동·추적 재생성 차단, 정지 중 보정 완료 대기를 포함한다. CAN 전송 파일은 변경 전과 바이트 단위로 동일하고 Nano/VM CAN 설정도 동일하다. CAN worker는 모의 라이브러리로 검사했으며 장비/CAN 연결, 실제 정지 거리·검출 성능 측정은 수행하지 않았다.
