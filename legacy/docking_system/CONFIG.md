# 공통 설정 입력 안내

수정할 파일은 `configs/common.json`이다. 네 버전이 같은 값을 사용한다. 파일은 표준 JSON이며, 각 항목의 `value`가 실제 값이고 `description`은 한글 설명이다. 상위 묶음의 항목들은 `fields` 안에 있다. 자동 보정·점검 결과 저장 시에도 설명을 유지한다.

```json
"camera_height_m": {
  "description": "바닥에서 카메라 광학 중심까지 높이[m]",
  "value": 0.57
}
```

아래 표는 읽기 편하게 `fields`와 마지막 `value`를 생략한 논리 경로다. 예를 들어 `values.sensor.rig.camera_height_m`은 파일에서 `values → fields → sensor → fields → rig → fields → camera_height_m → value`를 수정한다. `null`은 미입력이다. 일반 JSON 도구로 파일을 읽을 수 있고, Python에서 실행용 값만 얻을 때는 `common_config.read()`를 사용한다. 버전별 생성본·정책·로그에는 설명을 넣지 않는다.

## 직접 입력·확인

| 내용 | common.json 위치 | 현재 상태 |
|---|---|---|
| 태그 중심 높이 | `values.sensor.rig.tag_height_m` | 1.58, 현장 재확인 |
| 카메라 광학 중심 높이 | `values.sensor.rig.camera_height_m` | 0.57, 재장착 후 실측 |
| 카메라→포크 앞끝 | `values.sensor.rig.camera_to_fork_tip_m` | 1.50, 재확인 |
| 차체 기준점→뒤끝 | `values.body.rear_m` | 보수적 1.00, 실측 확정 아님 |
| 차폭의 절반 | `values.body.half_width_m` | 0.75, 폭 1.50m 상한 기준 |
| 카메라 좌우 위치 | `values.sensor.calibration.camera_lateral_m` | 사용자 지정 0.00m, 중앙 장착 가정. 왼쪽 + |
| 태그 ID·변 길이 | `values.sensor.tag.id`, `size_m` | 1 / 0.30, 흰 여백 제외 |
| 태그 입구 기준 위치·방향 | `sites.<작업>.sensor.calibration` | 중앙 태그 [0,0], 좌측 태그 [미정,1.0] 임시 |
| 실제 허용 공간 | `sites.<작업>.scene` | 미측정. `free_rectangles`와 `clearance_m` |
| 목표·허용 오차 | `values.trial`, 작업별 `sites.<작업>.trial` | 앞 0.50m 정지, 좌우 ±0.03m. 주차 깊이·방향 오차 미정 |
| 진입 전 정렬 구간 | `values.prealignment` 또는 작업별 `sites.<작업>.prealignment` | 통로 반폭·정렬 위치 등 미정 |
| 최초 회전 가능 반경 | `values.startup_search.free_radius_m` | 미측정 |

작업명은 `kw_wall_stop`(중앙 태그 앞 50cm 정지), `kw_park_left_tag`(좌측 태그를 사용해 안쪽에 주차)다. 기본값보다 `sites.<작업>`의 값이 우선하므로 작업별 공간·태그 위치는 해당 `sites`에 입력한다. `null`인 작업별 값도 기본값을 덮는다.

몸체 기준점은 **카메라 앞뒤 위치에 있는 차체 중심선의 지면 점**이다. 차체의 가로·세로 중앙이나 회전중심이 아니다. 뒤끝 거리는 회전 시 전체 차체 공간 계산에도 쓰인다. 3cm 목표 오차를 탑재부 실제 측면 간격으로 대체하지 않는다.

태그 설치 방향 `R_dock_tag`는 장착각 측정만으로 알아낼 수 없다. 현재 코드 좌표계에서 태그가 수직이고 윗변 수평이며 입구 바깥쪽을 향하는 기준 설치의 행렬은 `[[0,0,-1],[-1,0,0],[0,1,0]]`이다. 해당 설치를 확인한 경우에만 해당 작업의 값으로 사용한다. 태그가 기울어지거나 다른 방향이면 별도로 정해야 한다.

## 측정·계산으로 자동 작성

- `preflight.py mount`: 성공한 장착 방향 `R_body_camera`, `camera_model`, camera serial을 공통 값에 저장. 카메라 탈부착 후 다시 수행한다. 차체가 태그 면에 정확히 정렬돼 있어야 한다.
- 카메라 좌우 위치는 사용자 지정으로 0.00m(중앙 장착 가정)다. 장착각 측정에도 `mount --camera-lateral-m 0`을 함께 입력한다. 실측값으로 바꾸려면 해당 값을 사용한다. 생략하면 새 장착의 좌우 위치는 미측정으로 남긴다.
- `body.front_m`, `T_body_camera`, `T_dock_tag`는 구성요소로 계산한다. 해당 값들을 별도로 입력하지 않는다. 목표 `goal`도 작업의 정지거리·허용 오차로 계산한다.
- `preflight.py devices` / `inspect`: 장치 연결, FPS·처리 시간·누락·태그·IMU 상태를 `automatic`과 `calibration` 보고서에 저장한다. **기존 보정값이나 주행 승인으로 자동 대체하지 않는다.**
- IMU 초기 영점·중력축은 각 run에서 새로 측정한다. 앞 run에서 READY였다고 다음 run의 초기 보정을 건너뛰지 않는다.

## 매 실행의 출발 전 정지 측정

`values.startup_measurement`가 네 버전 공통 준비 절차다. 실주행에서 Enter를 누르면 CAN 중립을 유지하면서 IMU 초기 보정을 기다리고, 센서가 준비되고 정지가 확인된 뒤 연속 `duration_s` 동안 측정한다. 기본 60초이며 30초로 변경할 수 있다. IMU 준비 시간은 별도이며 전체 대기 제한은 `timeout_s=180`초다. 움직임·오래된 관측·추적 재시작·센서 간격 초과가 나타나면 정지 측정 구간을 새로 시작한다. 보정 실패·시계 오류·전체 시간 초과이면 출발하지 않는다. 준비가 끝나기 전에는 초기 태그 탐색 회전도 하지 않는다.

완료 후 기존 태그 확보/주행 조건을 확인하여 자동 진행한다. 정지 측정 동안의 태그 위치 흔들림, 정지 VO 변화, 영상별 IMU 관측과 초기 보정 결과, 수신 후 처리 시간, 중립 CAN 전송 상태를 실행 폴더의 `startup_measurement.json`에 남긴다. 영상별 IMU 통계는 200Hz 원시 데이터 전체 통계가 아니며, 원시 정지 보정 통계는 IMU 보정 결과에 별도로 포함된다. 태그가 안 보인 항목은 미측정으로 남고 기존 태그 확보 절차로 이어진다.

이 보고서는 이번 실행의 관측 결과다. 설정이나 정책의 오차 상한을 바꾸지 않으며, 절대 위치 정확도·이동 중 VO 오차·차량 출발/제동 지연을 측정한 것으로 해석하지 않는다. 정지 판정에 필요한 기존 검증값도 계속 요구한다. 준비 시간 변경 후에는 고정 주행 설정과 정책을 다시 생성한다.

## 별도 실험·검토가 필요한 값

`actions`의 이동/회전·제동·시작/정지 지연, `sensor.bounds`의 오차 상한, `limits`의 유효시간, CAN 진단 제한, 정지 판정·복귀·가시성 범위는 정지 카메라 검사만으로 채울 수 없다. `preflight.py check`가 필요한 값을 빠짐없이 표시한다. 정지 흔들림의 표준편차나 과거 평균값을 최대 오차/제동 범위에 대입하지 않는다.

`validation.*`, 각 `verified`는 실험 근거가 필요한 표시다. 알고리즘이 바뀐 검증과 VM의 지연 검증을 공통 물리 치수와 혼동하지 않는다. 실제 검증 완료 후 `prepare`로 고정 설정을 만들고 해당 버전/호스트의 검증·승인을 기록한 설정으로 정책을 생성한다. 공통 원본을 바꾸면 고정 설정과 정책도 다시 준비한다.

과거 v4의 회전중심은 카메라 앞 0.465m, 오른쪽 0.112m였다(출처: `apriltag_v4/config/control.py:31,34`). 실행하지 않는 참고값이므로 공통 설정에서 제거하고 이 문서에만 남겼다. 현 제어기 값으로 자동 적용하지 않았으며 카메라 좌우 위치나 차량 기준점으로 쓰지 않는다.

## 코드 업데이트 시 설정 보호

기본 업데이트는 **Jetson에 이미 있는 common.json을 유지**한다. 최초 설치 때만 맥북 파일을 복사한다. 맥북에서 공통 값을 수정해서 보내려는 경우에만 `update_jetson.sh --with-config`를 사용한다. 이 옵션은 Jetson의 측정 보정값도 맥북 파일 내용으로 교체하므로 어느 쪽을 기준으로 수정했는지 확인한다. 현장에서는 VS Code로 Jetson의 공통 파일을 직접 수정하는 것이 간단하다.
